# B → C 평가 입력 제안안 (v0.1, 미합의)

이 문서는 C가 평가 구현을 시작하기 위한 **임시 제안**이다. B와 합의하기 전까지
공통 계약인 `docs/interfaces.md`와 `contracts.py`를 바꾸지 않는다.

## 전체 흐름과 책임

`A 전처리 데이터 → B PPO 학습·비중 결정 → C 동일 조건 백테스트·성과/통계/SHAP 평가 → E FastAPI → Streamlit`

- A는 C에도 동일한 전처리 데이터와 KOSPI 벤치마크를 제공한다. 동일가중·MVO는 A와
  구현/입력 책임을 확인한 뒤 C가 DRL과 같은 날짜·비용·지표로 비교한다.
- D의 리스크 태그는 B의 최종 비중 결정에 반영된다. C는 태그 적용 전후를 구별해
  평가하고, E가 근거를 보여줄 수 있도록 결정 기록을 연결한다.
- B의 학습 보상값이나 학습 곡선은 **투자 성과 자체가 아니다**. C는 테스트 구간의
  일별 순수익률과 거래 기록으로 성과를 계산한다.
- E에는 C의 `EvaluationResult` 목록과 ANOVA·SHAP 결과를 API를 통해 전달한다.
  Streamlit은 파일을 직접 읽지 않고 API만 호출한다.

## B가 한 실험에 내보낼 최소 파일

경로는 `artifacts/runs/<experiment_id>/`이며, `experiment_id`는 세 파일에서
동일하다. `manifest.json`은 기존 `RunManifest` 계약을 그대로 쓴다. 테스트 기간은
`configs/experiments.yaml`에서 `window_id`로 찾는다.

### `portfolio_history.parquet`: 테스트 거래일마다 한 행

| 열 | 형식/단위 | 의미 |
|---|---|---|
| `date` | 날짜 | 수익률이 귀속되는 **테스트 거래일**. 중복 없이 오름차순 |
| `decision_as_of` | 날짜 | 해당 수익률에 적용한 비중을 결정할 때 사용한 마지막 데이터 날짜 |
| `portfolio_value` | 양수 실수 | 당일 수익·비용 반영 후 NAV. 첫 테스트일 직전 NAV는 1.0 |
| `gross_return` | 실수, 비율 | 당일 거래비용 차감 전 단순 수익률 |
| `net_return` | 실수, 비율 | 당일 모든 거래비용 차감 후 단순 수익률. C의 12개 지표·ANOVA 입력 |
| `turnover` | 0 이상 실수, 비율 | 당일 거래한 자산의 절대 거래금액 합 / 거래 직전 NAV |
| `transaction_cost` | 0 이상 실수, 비율 | 수수료·슬리피지로 차감한 금액 / 거래 직전 NAV |
| `safeguard_action` | 문자열 또는 null | MDD Safe-Guard가 개입했다면 조치 내용 |

같은 실험의 모든 행은 같은 회계 규칙을 적용한다. `portfolio_value`는 첫 행부터
`이전 NAV × (1 + net_return)`과 허용 오차 내에서 일치해야 한다. 결측 수익률을
0으로 채우거나 거래일을 조용히 삭제하지 않는다. 비용은 명세의 수수료 0.015%,
슬리피지 0.05%를 반영하며, 정확한 매수·매도 비용 계산식은 B·C가 확정한다.

### `weights_history.parquet`: 테스트 거래일 × 자산마다 한 행

| 열 | 형식/단위 | 의미 |
|---|---|---|
| `date` | 날짜 | 위 `portfolio_history.date`와 동일한 수익률 귀속일 |
| `decision_as_of` | 날짜 | 위 같은 날짜의 `decision_as_of`와 동일 |
| `ticker` | 문자열 | `configs/assets.yaml`의 11개 티커 중 하나 |
| `model_weight` | 0~1 비율 | PPO가 제안한 목표 비중, 리스크 규칙 적용 전 |
| `final_weight` | 0~1 비율 | 리스크 규칙·Safe-Guard 적용 후 목표 비중 |

날짜마다 11개 티커가 정확히 한 번씩 나타나고 자산 순서는 `assets.yaml`을 따른다.
두 비중 각각의 합은 1(허용 오차 `1e-4`)이며 공매도는 없다. 이 비중은 **목표 비중**이다.
가격 변동 후 실제 보유 비중과 혼동하지 않는다. 리스크 태그 적용 전후 비교 시에는
동일한 시장 데이터·모델·시드·비용을 쓰고 리스크 규칙 적용 여부만 바꿔 실행한다.

### `decisions.jsonl`: 결정 추적용 (평가 최소 입력과 별개)

`Decision` 계약의 JSON 객체를 결정일마다 한 줄씩 기록하는 안을 제안한다.
`decision_id`, `as_of`, `model_weights`, `final_weights`, `applied_tags`,
`applied_rules`, `safeguard_action`을 통해 C의 사례 분석과 E의 설명 화면을 연결한다.
SHAP 분석에 사용할 모델·정규화 정보·피처 순서는 B의 모델 묶음 및 `RunManifest`와
일치해야 한다. 원시 뉴스 본문은 이 파일에 넣지 않는다.

## C에서 적용할 입력 검증

1. `manifest.json`의 자산·피처 순서, 윈도우·시드·보상 종류를 설정과 비교한다.
2. 테스트 거래일과 티커를 A의 입력 데이터에 맞춰 검증한다. 누락·중복·NaN·무한대는
   자동 보정하지 않고 오류로 알린다.
3. `decision_as_of < date`를 기본으로 하여 당일 종가를 본 뒤 같은 종가에 체결하는
   미래 정보 누수를 막는다. 정확한 체결 시각은 B·C 합의가 필요하다.
4. `net_return`과 NAV의 재귀 관계, 비중 범위·합, 비용의 부호·단위를 검증한다.
5. C는 B의 `net_return`을 기준으로 A의 KOSPI `benchmark.simple_return`과
   동일 날짜에서 지표를 계산한다. 동일가중·MVO에도 같은 비용·평가 규칙을 적용한다.

## B·C 합의가 필요한 항목

1. **체결 시점:** 기준일 종가까지 관측 → 다음 거래일 체결/수익 귀속을 추천한다.
   시가 데이터가 없을 때 실제 체결가격·비용·수익률을 어떻게 근사할지 정해야 한다.
2. **회계식:** `gross_return`, `net_return`, `turnover`, `transaction_cost`의
   정확한 순서와 수수료·슬리피지 계산식. 동일가중·MVO도 그대로 사용해야 한다.
3. **Safe-Guard 조기 종료:** 종료 후 남은 테스트 기간을 현금으로 유지할지, 별도
   실패 실험으로 처리할지. 중간에서 기록을 끊고 다른 전략과 성과를 비교하면 안 된다.
4. **비중 의미:** 목표 비중의 적용일, 리밸런싱 주기, 현금 자산 포함 여부. 현재
   `Decision` 계약은 비중 합 1을 요구하고 `assets.yaml`에는 현금 티커가 없다.
5. **리스크 태그 비교:** 같은 PPO 모델로 태그 적용/미적용을 한 쌍으로 저장할
   실험 ID와 태그 공개 시각 검증 방식.
6. **설명 입력:** B 모델의 결정 시점 관측 벡터와 피처 순서, 정규화 통계 및 SHAP이
   설명할 출력(예: 특정 자산의 `model_weight`)을 함께 확정한다.

합의되면 이 문서를 기준으로 샘플 파일·검증 테스트를 만든 뒤 `docs/interfaces.md`와
공통 계약에 반영한다. 그 전에는 B의 구현 형식이 이미 확정된 것으로 취급하지 않는다.
